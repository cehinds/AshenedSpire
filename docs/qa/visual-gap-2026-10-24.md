## 0. Caveats about the reference

1. Fonts in the captures are fallbacks. The web CSS asks for `Cinzel` (display) and `Inter` (body) but declares no `@font-face` for them (`document.fonts` has nothing loaded; only the "AS Lore" card-lore faces have `@font-face`). In this container Inter happens to be installed system-wide, Cinzel is not, so every "Cinzel" heading renders as Liberation Serif (Georgia on a Windows/Mac player's machine). The intended faces exist as OFL files in the art release (`assets/fonts/cinzel-400-normal.woff2`, `inter-400-normal.woff2`). Target Cinzel+Inter (design intent) but expect owners to compare against a Georgia look; ask the owner which one is "the look".
2. The web defaults to its high-contrast palette (parchment `#fdf6e6`, muted `#a89571`, line `#6a5b43`, line-soft `#85714f`), not the base palette Unity's tokens copied.
3. A fresh web profile has only Reaver unlocked (the other classes show a lock); `shot=customize` shows the same (a rogue pose shot was dropped for that reason). The lock tile shows a stray text "progression" where an icon is missing (a web defect, do not copy).
4. `?shot=` states (memory storage, fixed seed) were used for most screens; everything is the web's own QA hook, no web code was changed. `combat-statuses-*` uses the web's fixture hook `window.__combat` + `__renderCombatForShot` (as the web's own browser test does). The main flow (startup gate to first fight, with its first-fight tutorial overlay) was driven with real input.

## 1. How the web was served and driven

`Tools/web-screens.mjs` mirrors the web repo (no .git/docs/tests) into a scratch folder, runs the web's own `tools/fetch-art.mjs` there to unpack the pinned public art release `hd-assets-v23` (~500 MB), serves the mirror with the web's own `serve()` and drives it with Playwright/Chromium. The web repo is never written. Output is JPEG q80 (PNG was too large for the budget).
