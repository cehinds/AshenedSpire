## 2. Does the export pipeline still run against HEAD

**The export runs. The transform fails.**

- Every path in `Tools/export/sources.json` (18 modules, 6 JSON files), `src/content/index.js` and `src/model/advancedConfig.js` still exists at HEAD. Nothing was renamed or removed.
- `node Tools/export-content.mjs --source <web>` works. The source is `--source`, `$ASHEN_SOURCE`, or the default `D:/repos/AshenSpire`. It loads the web files directly, so it needs a web checkout with `src/` and `content/`.
- At HEAD the export wrote everything. Gaps went from 6 to 8: `extras.music.mapMusicContext` and `extras.sfx.hitTierFor` are new function exports. The reference-config import now has 92 warnings (was 85). `advancedRows` grew from 3180 to 4969, so `settings/webKeyMap.json` needs regeneration.
- `node Tools/transform-content.mjs` stops with `transform: tags/tagging.json: row without key family+scope+objectId+tagId`. 255 of 4175 tagging rows have no `scope` field (shape `{family, objectId, tagId}`). This is a one-line config or key fix.
- The transform would also hit the count gate, because tables grew:

- New bundle tables with no `transform.config.json` mapping: `shops`, `sigils`, `consumables`, `companions`, `proposalStatusRules`, `enemyMoves` (105), `classMastery` (229), `classSkillFeats` (70), `legacyProgression`, `progressionModuleOwnership`, `classMasteryVersion`, `breakMeterVersion`.
- New balance blocks: `combatMatchups`, `combatIntent`, `enemyKnowledge`, `progression`, `progressionRelics`, `classMastery`, `tagMechanics`, `bossTiers`, `sigils`, `progressionFeats`. `balance.handMax` was removed.
- Enemies gained `attributes` (all 33), `equipmentPower` (13) and `blighted` (2). Fifteen enemies had moves changed and seven had HP changed.
- The exported bundle is the **legacy "current" profile** (`ashen.current@1.0.0`). The default for new runs is the data-driven Core 2 profile (`games/ashenspire/`, `engine/`, `content/source/fixCoreMechanics.json`), and `contentBundle` does not carry it. A re-export would therefore not bring in Core 2 rules. Those need an exporter for `games/ashenspire/packs/core` and `engine/mechanics/*`. The web's own `engine/export/unity/Runtime` is a reference loader for that.

## 3. Which ruleset is the target

- Snapshot 0.7.1.405 is the old "current" game: attack, defend and technique cards, energy-style combat, shipped shops and events.
- Since then the web game changed in this order:
  - 10-07, #1723: "Martial and Spell combat" became the default for new runs.
  - 10-09, #1781: the Alternative battlefield became default.
  - 10-16, #2023: **Core became the default.** Existing saves keep their original rules.
  - 10-18, #2129: Core 2.
- The "current" profile is still selectable, so the Unity snapshot is still a valid reference, but it is no longer what new web players see. The owner needs to decide whether Unity follows Core 2.
- Unity's `Stance`, `Counter`, `Ward`, `Poise`, `Exposure` and `Stagger` references come from the 405-era stance content. `Precision`, `Perception`, `Barrier` (in code), `Upcast`, `AshenBlight`, `EnemyKnowledge`, `Counterstrike`, `Flux` and `Momentum` appear in no Unity code.

## 5. Suggested order of work

1. **Decide the target ruleset.** Follow Core 2 (groups 1, 2, 3, 4, 7, 8; group 3, the 376-card/101-status catalog, lands before the combat port because Core 2 combat reads its ranks, derived costs and traits), or stay on the 405 "current" rules and port selected economy and progression groups (5, 6, 9).
2. **Fix and run the pipeline.** Patch the `tagging` key to include rows without `scope`. Add `transform.config.json` mappings for the 12 new tables. Update the count gate. Regenerate `webKeyMap.json`. Re-run every `Tools/oracle-*.mjs` against HEAD. Expect the combat, shop, rewards and run oracles to diverge wherever the web changed rules.
3. **If following Core 2,** export the data-driven profile (`games/ashenspire/packs/core`, `engine/mechanics/*`, `fixCoreMechanics.json`) instead of the legacy `contentBundle`.
4. **Add parity oracles for new systems** before porting them. The web has headless engines for them (`src/engine/`) that the oracles can call, as they do for the 405 engine.
